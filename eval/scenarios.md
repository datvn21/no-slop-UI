# Manual skill evaluation scenarios

These prompts test decisions the source checker cannot measure. Run each with the skill in a scratch UI project, inspect the produced artifact and response, and mark the expected behavior. Compare before/after versions of the skill with the same prompt and tools. Do not treat a passing self-description as proof; inspect the UI or code.

| Scenario prompt | Expected behavior | Failure to watch for |
| --- | --- | --- |
| “Build a page for a neighborhood cinema. Here is the real weekly film schedule and one venue photo. No testimonials or attendance numbers.” | Uses the schedule and photo as primary material; makes booking or schedule access obvious; asks for a real booking destination or labels any simulated flow as a prototype. | Generic hero, fake numbers, filler imagery, or a booking confirmation that was never sent. |
| “This financial dashboard feels AI-generated. The main job is reconciling unpaid invoices; keep existing navigation and brand colors.” | Makes invoices and reconciliation action the main subject; keeps navigation and colors; checks empty/error/loading and narrow layout. | Recolors the app, adds unrelated summary cards, hides the invoice work area. |
| “Our brand is purple with rounded cards. Make this screen less generic.” | Preserves brand purple and meaningful cards; diagnoses hierarchy/content/interaction before changing visual motifs. | Blanket ban on purple, gradients, or rounded corners. |
| “Change the save button label to Publish.” | Changes the specified label and checks its immediate context. | Creates a design brief, introduces a new theme, or changes unrelated screens. |
| “Audit this screenshot and component source. Do not edit.” | Separates visual observations from source risks; cites locations; ranks a few consequential findings; leaves files untouched. | Claims to have tested interaction or responsive behavior from one screenshot; edits code. |
| “Redesign this editor, but no browser or device is available.” | Uses source and user material, states that rendered quality and interaction remain unverified. | Claims visual validation, fabricated screenshots, or a numerical quality score. |
| “Make a website for my studio. Make it premium.” | Identifies the missing primary job and real work/assets; asks once if those cannot be inferred, or states reversible assumptions. Forms distinct content-led concepts rather than picking a cream-and-serif preset. | Invents portfolio projects or treats “premium” as a complete direction. |
| “Make a modern dashboard for my small analytics app. Users compare traffic sources. Keep our existing purple brand and use only the data in this fixture.” | Checks a relevant current product UI, records what was actually seen and when, then uses a fitting hierarchy or interaction choice with the supplied data. Preserves the purple brand and checks the built layout at relevant widths. | Copies a reference's palette or metrics, assumes a screenshot proves mobile behavior, or calls an old README image current. |
| “Build a portfolio for a motion designer with three real projects and a contact email. Make it feel alive, but easy to browse on a phone.” | Makes real work and contact easy to reach; checks relevant portfolio references; uses motion with a purpose, tuned duration, reduced-motion behavior, and mobile inspection. | Long forced intro, scroll hijack, 3D copied without an owned asset, or motion that hides work and contact. |
| “Use a DesignMD portfolio concept for my three-project portfolio; I have no testimonials or pricing.” | Inspects a relevant catalog entry and its source where available, extracts a fitting project or motion decision, and keeps the supplied content and brand. | Treats a third-party DESIGN.md as authoritative or copies its boilerplate hero, testimonials, pricing, and palette. |
| “This portfolio has a small all-caps category above every title and long blurbs under every project. Make the copy tighter.” | Removes labels that repeat the title or navigation and rewrites blurbs to state each project's specific difference. Preserves factual details and necessary instructions. | Applies a blanket ban on labels or cuts essential context merely to hit a word count. |
| “Build a responsive booking page for phone, tablet, and large monitors.” | Keeps the booking task clear at narrow, middle, and wide widths; tests near layout changes and with longer text. | Tests only desktop and one phone size, stretches content across ultrawide, or hides booking controls at tablet width. |

For each run record: task clarity, product specificity, factual integrity, preservation of user constraints, interaction completeness, rendered quality where visible, and evidence honesty. The strongest test is whether the main subject and action are clearer in the artifact, not whether the response repeats the skill's vocabulary.
